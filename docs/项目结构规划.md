# 项目结构规划

> 本文根据当前《策划.md》整理。下方先记录已实现的样式预览结构，再列出后续页面的建议模块边界。

## 1. 项目形态

按已确认的方向，先按**纯前端静态网页 / 剧情演示**规划：页面读取仓库内的 JSON 数据，在浏览器中完成页面切换、匿名身份展示、管理员查询和解锁状态管理。

这意味着账号密码、管理员校验答案和私信数据都不能视为真正保密的信息。静态网页中的代码和 JSON 可被访问或修改；浏览器本地保存的解锁状态也只适合演示，不构成访问控制。若将来要保护真实用户或私信，需要另行加入后端认证与授权。

目前没有既定框架或依赖。当前预览使用原生 HTML、CSS 和 JavaScript，无需安装依赖；主页、搜索页逻辑与共享导航组件分开放置。登录页和主页共用深色赛博朋克底色与青蓝、粉、紫霓虹视觉；主页以蓝紫和粉色为主，不使用荧光绿作为主色。

### 当前预览范围与差异

- `index.html` 是入口；浏览器本地没有登录标记时跳转到 `pages/log_in.html`。登录成功后保存本地登录标记、展示头像和昵称，并等待一秒返回主页。登录页在已有登录标记时也会直接返回主页。
- 演示账号和密码暂时都是 `888888`，位于 `assets/js/forum.js` 文件开头，便于修改。由于校验完全在浏览器端，这只是样式演示，不是真正的账号安全机制。
- 主页版块为“兴趣爱好”“闲聊吐槽”“求助答疑”“站务公告”；其中“兴趣爱好”“闲聊吐槽”和“站务公告”均取自现有帖子，“求助答疑”目前尚无帖子。个人主页及管理员页面目前只提供样式或占位提示。
- 主页采用简洁布局：活跃用户信息与搜索框并排显示；版块以标签页形式筛选并显示对应帖子列表，不再把版块和讨论拆成卡片区。没有“全部”标签，初始显示“兴趣爱好”版块。当前主页可见的帖子包括 P01（“兴趣爱好”）和 P06（“站务公告”）；P02（“闲聊吐槽”）为仅搜索帖子。
- 导航栏由 `assets/js/navigation.js` 独立生成并挂载到页面的组件容器；后续页面可以复用此组件，不必在各 HTML 中重复编写导航栏结构。
- 讨论列表仅在标题上方展示置顶/版块标签，标题下显示“楼主：昵称”，不展示正文预览。匿名帖的匿名昵称由该帖 `anonymousIdentities` 数组按真实用户 ID 直接映射；管理员用户 ID `0` 是例外，即使帖子设为匿名也始终显示真实昵称。
- P01 和 P06 均为匿名帖；P01 楼主的真实 ID 为 `1`，其显示昵称由该帖映射决定；P06 楼主是管理员 ID `0`，即使帖子匿名也显示“萌萌小兔兔宝宝”。
- 主页只保留中文导航、内容和必要状态信息；移除了品牌英文副标、社区状态展示卡、英文栏目标签、地理位置字样和帖子列表头像图标。
- 现有帖子 JSON 没有发布时间，因此当前预览从 `texts/posts/index.json` 加载帖子，但尚不能按最近一周筛选；页面上的近期/活跃人数说明是按策划案展示的文案。
- 主页帖子列表只显示 `meta["search-only"]` 为 `false` 的帖子；标记为 `true` 的帖子仅出现在搜索结果中。搜索在 `meta.keywords` 中进行，忽略大小写并去除空白后按子串匹配。
- 使用 `fetch` 读取帖子 JSON 时，应通过本地静态网页服务器或静态托管打开 `index.html`；直接以 `file://` 打开无法可靠读取 JSON 文件。

## 3. 后续模块建议

随着剩余页面实现，可将当前集中在 `assets/js/forum.js` 的逻辑拆分为以下职责：

- `router`：页面路由与地址参数。
- `components`：共用导航栏、页脚、帖子列表、用户资料卡片。
- `pages`：主页、搜索、管理员功能、用户查询、帖子详情、用户主页和私信页面。
- `services`：帖子及私信 JSON 加载、搜索、演示登录、用户查询校验、匿名身份解析和解锁状态存储。
- `styles`：按全局基础、页面布局和共用组件继续拆分 CSS。

### 静态内容发现方式

浏览器端不能像服务器程序一样直接列出某个目录中的所有文件。因此，主页和搜索页先读取 `texts/posts/index.json`，再逐一读取清单中的帖子 JSON。新增帖子时需同步更新清单；私信目录未来也可采用同样方式。

## 4. 页面与共用界面

- **登录页**：独立于登录后的共用布局；验证成功后展示指定管理员昵称和头像、显示加载状态，再延迟一秒进入主页。当前预览的账号和密码均为 `888888`。
- **导航栏与页脚**：登录后页面共用；登录页不显示。导航链接至个人主页、管理员功能及退出登录。
- **主页**：展示版块、搜索入口和近期帖子；“最近一周”和“6 位活跃用户”等文案按策划案呈现。活跃人数是否固定显示还是从数据计算，仍需确认。
- **搜索页**：`pages/search.html` 显示搜索输入框、当前关键词和匹配帖子列表。关键词经去除空白并忽略大小写后，在每篇帖子的 `meta.keywords` 中按子串匹配；搜索结果包括仅供搜索的帖子。
- **管理员功能与用户查询页**：其他功能以不可用提示呈现；用户查询表单在校验成功后展示对应用户入口。
- **帖子页**：从主页标题链接进入，按清单中的帖子 JSON 展示楼主内容和回复；匿名身份按该帖映射显示，回复提交按钮禁用。
- **用户主页**：展示用户资料和私信入口；私信入口标明仅管理员可用。
- **私信页**：管理员自己的页面为空；其他对话只有在双方用户都已解锁时才显示。

所有展示用户身份的页面都应调用同一身份解析逻辑，而不是各自判断匿名状态。这样解锁后，帖子列表、帖子正文、回复和用户链接才能一致地显示原始头像与昵称。

## 5. 状态与主要数据流

1. 应用启动时解析当前页面地址，并从内容清单加载所需 JSON。
2. 登录状态控制能否进入登录后的页面；管理员页面和管理员私信入口依策划设定显示。
3. 管理员提交用户资料答案后，由查询校验逻辑确认匹配；成功时把该用户 ID 记录到浏览器本地存储。
4. 解锁记录按用户 ID 保存，供后续访问的各页面读取；刷新页面或重新打开浏览器后仍保留。此状态仅用于剧情演示，用户可自行修改。
5. 帖子渲染时，根据帖子是否匿名、参与用户及解锁记录决定显示原始身份或匿名身份。
6. 私信显示前检查对话双方是否都已解锁；检查失败时不渲染消息内容。

为适配普通静态托管，可以考虑用 URL 哈希承载页面和查询参数，避免依赖服务器配置前端路由回退；最终路由形式留待实现前确认。

## 6. 目前明确与待补充的策划信息

### 已明确

- 赛博朋克暗色风格与荧光 UI。
- 登录后页面共用导航栏和页脚，登录页除外。
- 管理员昵称、登录成功后的等待时间、禁用回复功能等指定展示行为。
- 帖子和私信采用 JSON 内容文件。
- 解锁状态在刷新和重新打开浏览器后保留。
- 匿名身份在每篇匿名帖的 `anonymousIdentities` 数组中明确映射；同一用户可以在不同帖子中使用不同匿名身份。
- 帖子作者和回复作者字段始终保存真实用户 ID；解锁后应显示对应用户的真实昵称和头像，而不是改写帖子源数据。

### 实现前待补

- `messages` 的 JSON 字段、字段类型、示例文件及缺失数据处理规则。
- 演示登录账号密码，以及用户查询所需答案与对应用户数据。
- 全部版块名称、用户资料字段和职业选项清单。
- “最近一周活跃用户共有 6 人”是固定文案还是按内容计算。
- URL 路由格式、目标部署环境和是否需要兼容 `file://` 直接打开。

以上待补信息未明确前，不要在代码中臆造私信 JSON 格式或用户查询验证答案。

### 帖子 JSON 约定

- `meta.board`、`meta.title`、`meta.author_id`、`meta.isAnonymous`、`meta.pinned` 和 `meta.keywords` 描述帖子元数据；作者 ID 对应 `configs/users.json` 中的用户 `id`。
- `content` 是正文字符串；`replies` 是按展示顺序排列的数组，每项包含真实用户 ID `authorId` 和回复文本 `content`。
- `anonymousIdentities` 是长度固定为 6 的整数数组。数组下标 `0` 至 `5` 分别对应真实用户 ID `1` 至 `6`；每个数组值是 `configs/anonymous.json` 中的匿名身份 ID。每篇匿名帖各自保存映射，同一用户在不同帖子里可以对应不同匿名身份。
- `meta.isAnonymous` 为 `false` 时始终展示 `configs/users.json` 中的真实昵称和 `avatar_path`；为 `true` 时未解锁用户展示该帖映射的匿名身份，解锁后展示用户配置中的真实昵称和头像。真实作者 ID 始终保留在 JSON 中，不因展示匿名而替换。
- `configs/users.json` 中每位用户使用 `avatar_path` 字段记录相对于项目根目录的真实头像路径；非匿名帖的楼主和回复均按真实用户 ID 加载昵称与头像。
- `meta.author_id` 为管理员 ID `0` 时，按现有规则即使帖子匿名也展示管理员身份；该管理员不占用上述六个匿名身份映射位置。
- `meta["search-only"]` 是必填布尔值：`false` 的帖子显示在主页列表中，`true` 的帖子只通过关键词搜索显示，不出现在主页列表中。
- 首页按每篇匿名帖的映射展示匿名昵称；帖子详情页展示对应匿名昵称和头像。匿名解锁后的真实身份切换尚未实现。

## 7. 建议实施顺序

1. 补全私信 JSON 样例，以及登录和用户查询的演示数据。
2. 确定静态托管方式和路由方案，建立应用入口、全局样式及共用导航/页脚。
3. 实现 JSON 清单加载和基础页面：主页、搜索结果、版块帖子列表、帖子详情、用户主页。
4. 实现匿名身份解析、管理员查询、持久化解锁状态及私信双方解锁检查。
5. 完善禁用功能提示、登录过渡状态和响应式视觉细节。
6. 验证页面跳转、刷新后解锁状态、匿名展示一致性、私信访问条件及 JSON 加载失败提示。
