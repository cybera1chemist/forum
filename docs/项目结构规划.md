# 项目结构规划

> 本文根据当前《策划.md》整理，是后续实现的建议，不代表已经确定的技术选型或数据格式。当前仓库只有空的 `index.html`、少量静态资源和内容目录，尚无应用代码或前端构建配置。

## 1. 项目形态

按已确认的方向，先按**纯前端静态网页 / 剧情演示**规划：页面读取仓库内的 JSON 数据，在浏览器中完成页面切换、匿名身份展示、管理员查询和解锁状态管理。

这意味着账号密码、管理员校验答案和私信数据都不能视为真正保密的信息。静态网页中的代码和 JSON 可被访问或修改；浏览器本地保存的解锁状态也只适合演示，不构成访问控制。若将来要保护真实用户或私信，需要另行加入后端认证与授权。

目前没有既定框架或依赖。建议先保持前端模块边界清晰，不在本规划中锁定框架；开始实现前再根据部署方式决定是否引入构建工具。

### 静态内容发现方式

浏览器端不能像服务器程序一样直接列出某个目录中的所有文件。因此，即使帖子保存在 `texts/posts/` 中，前端也需要先读取一个明确的清单文件（例如 `texts/posts/index.json`），再逐一读取清单中的帖子 JSON。私信目录也采用同样方式。清单格式和由谁维护目前未定；可以先人工维护，若未来增加构建工具再考虑自动生成。

## 3. 页面与共用界面

- **登录页**：独立于登录后的共用布局；验证成功后展示指定管理员昵称和头像、显示加载状态，再延迟一秒进入主页。真实账号密码尚未提供，不在规划中编造。
- **导航栏与页脚**：登录后页面共用；登录页不显示。导航链接至个人主页、管理员功能及退出登录。
- **主页**：展示版块、搜索入口和近期帖子；“最近一周”和“6 位活跃用户”等文案按策划案呈现。活跃人数是否固定显示还是从数据计算，仍需确认。
- **搜索页**：显示搜索输入框、当前关键词和匹配帖子列表；匹配规则尚待策划补完。
- **管理员功能与用户查询页**：其他功能以不可用提示呈现；用户查询表单在校验成功后展示对应用户入口。
- **帖子页**：展示楼主内容及回复；回复输入框只作展示，提交按钮禁用。
- **用户主页**：展示用户资料和私信入口；私信入口标明仅管理员可用。
- **私信页**：管理员自己的页面为空；其他对话只有在双方用户都已解锁时才显示。

所有展示用户身份的页面都应调用同一身份解析逻辑，而不是各自判断匿名状态。这样解锁后，帖子列表、帖子正文、回复和用户链接才能一致地显示原始头像与昵称。

## 4. 状态与主要数据流

1. 应用启动时解析当前页面地址，并从内容清单加载所需 JSON。
2. 登录状态控制能否进入登录后的页面；管理员页面和管理员私信入口依策划设定显示。
3. 管理员提交用户资料答案后，由查询校验逻辑确认匹配；成功时把该用户 ID 记录到浏览器本地存储。
4. 解锁记录按用户 ID 保存，供后续访问的各页面读取；刷新页面或重新打开浏览器后仍保留。此状态仅用于剧情演示，用户可自行修改。
5. 帖子渲染时，根据帖子是否匿名、参与用户及解锁记录决定显示原始身份或匿名身份。
6. 私信显示前检查对话双方是否都已解锁；检查失败时不渲染消息内容。

为适配普通静态托管，可以考虑用 URL 哈希承载页面和查询参数，避免依赖服务器配置前端路由回退；最终路由形式留待实现前确认。

## 5. 目前明确与待补充的策划信息

### 已明确

- 赛博朋克暗色风格与荧光 UI。
- 登录后页面共用导航栏和页脚，登录页除外。
- 管理员昵称、登录成功后的等待时间、禁用回复功能等指定展示行为。
- 帖子和私信采用 JSON 内容文件。
- 解锁状态在刷新和重新打开浏览器后保留。
- 匿名身份按帖子分别随机分配，而不是在所有帖子间共用同一身份。

### 实现前待补

- 搜索词如何匹配标题、正文、回复或其他字段；是否区分大小写、是否支持多个关键词。
- `posts` 与 `messages` 的 JSON 字段、字段类型、示例文件及缺失数据处理规则。
- 演示登录账号密码，以及用户查询所需答案与对应用户数据。
- 全部版块名称、用户资料字段、头像资源和职业选项清单。
- “最近一周活跃用户共有 6 人”是固定文案还是按内容计算。
- 匿名昵称和头像的候选集合；随机身份在刷新、重复访问同一帖子后是否保持不变。
- URL 路由格式、目标部署环境和是否需要兼容 `file://` 直接打开。

以上信息未补齐前，先不要在代码中臆造搜索行为、JSON 格式、验证答案或随机身份持久化规则。

## 6. 建议实施顺序

1. 补全搜索规则、帖子/私信 JSON 样例，以及登录和用户查询的演示数据。
2. 确定静态托管方式和路由方案，建立应用入口、全局样式及共用导航/页脚。
3. 实现 JSON 清单加载和基础页面：主页、版块帖子列表、帖子详情、用户主页。
4. 实现匿名身份解析、管理员查询、持久化解锁状态及私信双方解锁检查。
5. 实现搜索、禁用功能提示、登录过渡状态和响应式视觉细节。
6. 验证页面跳转、刷新后解锁状态、匿名展示一致性、私信访问条件及 JSON 加载失败提示。
